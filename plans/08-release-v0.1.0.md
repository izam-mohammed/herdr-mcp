# herdr-mcp installs with one command on Linux and macOS, without a Rust toolchain

## The ask

`features.md` § Non-functional: "Install: one command, no setup step.
Registered with `claude mcp add herdr -- <command>`", on the platforms
herdr runs on (Linux and macOS). Until now the binary is built from source
(plan 01).

## Alternatives

### Decision 1: how is the binary distributed? (two-way door)

Searched 2026-10-22: "cargo-dist axodotdev dist 2026 release prebuilt
binaries", "cargo-binstall"; package listings for dist 0.32.0, a 2026
deployment survey, generated `release.yml` files in other projects.

| Must | `cargo install --git` | GitHub Releases built by `dist`, with its shell installer | An npm package wrapping the binary (`npx`) |
| --- | --- | --- | --- |
| Works without a Rust toolchain | no | yes | yes (needs node) |
| Linux and macOS, x86_64 and arm64 | yes, built locally | yes | yes |
| **Survives** | no | **yes** | **yes** |

| Criterion | Weight | `dist` releases | npm wrapper |
| --- | ---: | ---: | ---: |
| Performance efficiency | 50 | 5 | 2 |
| Running cost and operability | 25 | 5 | 3 |
| Security | 25 | 4 | 3 |
| **Weighted total** | **100** | **4.75** | **2.50** |

- Efficiency: the `dist` binary starts directly (1.4 ms measured in plan
  01); `npx` starts node first, ~128 ms before the server runs (plan 01's
  Node measurement).
- Operability: one static binary on `PATH` against a node runtime plus a
  postinstall step.
- Security: `dist` publishes checksums with each release; npm adds a
  registry and install scripts to the chain.

Sensitivity: equal weights still give `dist` 4.67 against 2.67.
Risk: the generated `release.yml` must not be hand-edited, or releases
fail; customisation goes through `dist`'s config.

**Chosen: GitHub Releases built by `dist`.** Revisit if users need
Windows, which herdr does not support today.

## The decision

Feature context. `dist` generates `.github/workflows/release.yml` for
`x86_64` and `aarch64` on Linux (`-unknown-linux-gnu` and `-musl`) and
macOS, triggered by a `v*` tag, publishing archives, checksums and a shell
installer. The README's install becomes the installer one-liner, then
`claude mcp add herdr -- herdr-mcp`; `cargo binstall herdr-mcp` works from
the same releases. A CHANGELOG starts at the first tag.

Dependencies and permissions: `dist` (development tool only), and the
repository's GitHub Actions `contents: write` permission for the release
job. The repository is private today (`izam-mohammed/herdr-mcp`), so the
installer URL only works for people with access until it is made public;
see `## Open decisions`.

Standards: `docs/standards.md` (format, lint, tests, audit, secret scan,
shell check and build through `sh scripts/check.sh`); this plan adds the
release workflow and updates its CI section.

## Security

What is protected: the binary people install and run with access to their
terminals. Who can reach it: anyone who can push a `v*` tag.

| Threat | Here | Handled by | Proved by |
| --- | --- | --- | --- |
| Tampering | a release asset swapped or corrupted | checksums published by `dist`, verified by its installer | the installer's own check, run in the try |
| Elevation of privilege | the release job's token used for more than releasing | `contents: write` on the release job only; other jobs read-only | review of `release.yml` in Phase 2 |
| Tampering | a dependency compromised before release | `cargo deny check` in the check, which the release job runs first | `scripts/check.sh` in the workflow |

Checklist: SLSA build track (current spec, searched 2026-10-22) for what a
release pipeline should hold; level 1 (provenance exists) is the target
here.

## Open decisions

- Making the repository public, which the installer one-liner needs for
  anyone without access: default, keep it private and document
  `gh release download` for people with access.
- The licence: settled, MIT (`plans/12-repo-hygiene.md`, `LICENSE`).

## Rollback

Delete the GitHub release and its tag; earlier releases stay. The
workflow file is removed by reverting the commit.

## Declined

- `cargo install --git` (decision 1): needs a Rust toolchain.
- An npm wrapper (decision 1): adds ~128 ms of node start to every session
  and a postinstall step.

## What the tests hold

The release workflow runs on a pre-release tag and produces archives for
every target with checksums; the installer puts a binary on `PATH` that
answers `--version`; `claude mcp add` with it works in the try.
