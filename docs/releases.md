# herdr-mcp: how it is released

Every version is a GitHub release, built by `.github/workflows/release.yml`
(generated by `dist`, with two hand edits below) when a tag `vX.Y.Z` is pushed. The only hand step is
merging the release plan's PR and pushing that tag. There is no other
channel to publish to yet. Nothing is published by hand.

## Versioning

Semantic versioning, `vMAJOR.MINOR.PATCH`. The version lives in
`Cargo.toml` and `CHANGELOG.md` names what changed. `0.x` until the tool
names and flags in `plans/01-first-version.md` `## Contract` are declared
stable; that is `v1.0.0`, decided after `v0.3.0` has been used for a while,
since tool names are what people write permission rules against.

## Channels

Decided in `plans/08-release-v0.1.0.md` decision 1.

| Rank | Channel | For | Score | Workflow | Install check |
| --- | --- | --- | --- | --- | --- |
| 1 (recommended) | `dist` shell installer | Linux and macOS, no Rust needed | 4.75 | `release.yml` | `herdr-mcp --version` after the one-liner |
| 2 | `cargo binstall --git <repo> herdr-mcp` | people with cargo | 4.75 | `release.yml` (same archives) | `herdr-mcp --version` |
| - | GitHub Releases | everyone, the source | - | `release.yml` | download an archive, `sha256sum -c` its `.sha256` |

The crate is not on crates.io, so binstall needs `--git`; `Cargo.toml`'s
`[package.metadata.binstall]` points it at the `dist` archives. While the
repository is private the one-liner installer cannot fetch anything for
anyone: people with access use `gh release download` (README, Install)
until the repository is made public (an open decision, plan 08).

## Assets

Per release: an archive for each of `x86_64` and `aarch64` on Linux (gnu
and musl) and macOS (`herdr-mcp-<target>.tar.xz`), a `.sha256` per archive
and a combined `sha256.sum` (`dist` names them so, not `SHA256SUMS`), the
source tarball, and the shell installer. No provenance: `dist`'s
attestations are experimental and off (SLSA level 1 is the target: the
build is scripted and the checksums exist). Windows is out: herdr does not
run there.

## Workflows

- `release.yml`: starts on a pushed version tag (`v0.1.0`; a suffix such as
  `v0.1.0-rc.1` makes a pre-release), runs `scripts/check.sh` first (its
  `check` job calls `check.yml`), builds every target and creates the GitHub
  release. `contents: write` on the `host` job only; the workflow token is
  read-only. On pull requests it only runs `dist plan`. Changes go through
  `dist-workspace.toml` and `dist generate` where `dist` can express them.
- No `publish-<channel>.yml` yet: no second channel is planned. Homebrew and
  Scoop were not weighed; add them here with a score when someone asks.

## Hand edits to release.yml

`dist` 0.34.0 cannot express two things the plan needs (`docs/external/dist.md`,
"Known limits"): it writes `contents: write` at workflow level, and its
custom plan jobs render an invalid `uses: $/...`. So `dist-workspace.toml`
sets `allow-dirty = ["ci"]` and `release.yml` carries two marked edits:

1. a `check` job (calls `check.yml`, which has `workflow_call`) that `plan`
   needs, skipped on pull requests where `check.yml` already runs;
2. `permissions: contents: read` at the top, and `contents: write` on the
   `host` job alone.

To upgrade `dist`: run `dist generate` into a copy, diff against
`release.yml`, and re-apply the two edits; `dist generate --check` does not
guard the file while `allow-dirty` is set. Drop both edits and `allow-dirty`
when a `dist` release fixes the limits.

## Cutting a release

1. Merge the changelog and version bump (`Cargo.toml`, `CHANGELOG.md`).
2. Push the tag `vX.Y.Z`; push `vX.Y.Z-rc.N` first for a dry run (a
   pre-release, so `latest` does not move).
3. Check the release lists every target with checksums, then run the
   installer (or `gh release download`) and `herdr-mcp --version`.

## Install

The README's `## Install` leads with the shell installer, then `cargo
binstall --git`, then a release download, each with its `--version` check, how to
upgrade and how to remove it. Written in `plans/08-release-v0.1.0.md`.

## Decided

- `dist` releases over `cargo install --git` and an npm wrapper: no Rust
  toolchain needed, no node start cost (`plans/08-release-v0.1.0.md` decision 1).
- `v0.1.0` is released by `plans/08-release-v0.1.0.md` itself; later versions have
  their own `plans/NN-release-vX.Y.Z.md` (13, 14, 15).
- Licence MIT (`plans/12-repo-hygiene.md`).
