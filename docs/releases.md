# herdr-mcp: how it is released

Every version is a GitHub release, built by `.github/workflows/release.yml`
(generated by `dist`) when a tag `vX.Y.Z` is pushed. The only hand step is
merging the release plan's PR and pushing that tag. There is no other
channel to publish to yet. Nothing is published by hand.

## Versioning

Semantic versioning, `vMAJOR.MINOR.PATCH`. The version lives in
`Cargo.toml` and `CHANGELOG.md` names what changed. `0.x` until the tool
names and flags in `plans/01-first-version.md` `## Contract` are declared
stable; that is `v1.0.0`, decided after `v0.3.0` has been used for a while,
since tool names are what people write permission rules against.

## Assets

Per release: an archive for each of `x86_64` and `aarch64` on Linux (gnu
and musl) and macOS, `SHA256SUMS`, the shell installer, and provenance
where `dist` emits it. Windows is out: herdr does not run there.

## Workflows

- `release.yml`: starts on a pushed `v*` tag, runs `scripts/check.sh`, builds
  every target and creates the GitHub release. `contents: write` on that job
  only. Never hand-edited; changes go through `dist`'s config.
- No `publish-<channel>.yml` yet: no second channel is planned. Homebrew and
  Scoop were not weighed; add them here with a score when someone asks.

## Install

The README's `## Install` leads with the shell installer, then `cargo
binstall`, then a release download, each with its `--version` check, how to
upgrade and how to remove it. Written in `plans/08-release.md`.

## Decided

- `dist` releases over `cargo install --git` and an npm wrapper: no Rust
  toolchain needed, no node start cost (`plans/08-release.md` decision 1).
- `v0.1.0` is released by `plans/08-release.md` itself; later versions have
  their own `plans/NN-release-vX.Y.Z.md` (13, 14, 15).
- Licence MIT (`plans/12-repo-hygiene.md`).
